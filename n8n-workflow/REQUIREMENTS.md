# n8n Workflow (အသစ်) — လိုအပ်ချက်မှတ်စု

> အဆင့်ဆင့် ပြောပြထားသမျှကို ဒီဖိုင်မှာ မှတ်သွားမယ်။ အကုန်ပြည့်စုံမှ workflow JSON ဆောက်မယ်။

## အပိုင်း (၁) — Link လက်ခံခြင်း + Gemini Script

1. **ဘယ် link ပို့ပို့ လက်ခံနိုင်ရမယ်**
   - ပို့လိုက်တဲ့ video link (ဘယ် platform ကဖြစ်‌ဖြစ်) ကို လက်ခံပြီး အလုပ် စနိုင်ရမယ်။

2. **MB များသည် နည်းသည် မရွေးရ**
   - File size ကြီးသည် သေးသည် ကြောင့် ပယ်ချခြင်း မရှိရ။
   - (နည်းပညာ မှတ်စု: ဖိုင်ကြီးလာရင် အပိုင်းခွဲ/chunk လုပ်ပြီး ကိုင်တွယ်မည့် ဒီဇိုင်းမျိုး စဉ်းစားရမယ် — နောက်အပိုင်းတွေ ကြားပြီးမှ ဆုံးဖြတ်မယ်။)

3. **Script ကို Gemini နဲ့ ရေးခိုင်းမယ်**
   - ဒေါင်းထားတဲ့ video ကိုကြည့်ပြီး Gemini က script ရေးမယ်။

4. **Script ပမာဏ = မူလ video ကြာချိန်ရဲ့ 90%**
   - ဥပမာ: video ၁၀ မိနစ်ရှည်ရင် script ကို အသံဖတ်ရင် ~၉ မိနစ် ကြာတဲ့ ပမာဏ ရေးရမယ်။
   - 90% မပြည့်ရင် လိုတဲ့အပိုင်းကို ထပ်ဖြည့်ရေး (top-up) တဲ့ အဆင့်လိုမယ်။

## အပိုင်း (၂) — အဆင့်လိုက် Flow (26 Oct 2026 ပြောပြချက်)

1. **Transcript အရင်ထုတ်မယ်**
   - Link ကရတဲ့ video ကို transcript တစ်ဦး/တစ်ခုခုက အရင်လုပ်ပေးမယ်။
   - ⚠️ timestamps (start/end စက္ကန့်) ပါတဲ့ transcript လိုပါမယ် — နောက်ဆုံး video ဖြတ်တဲ့နေရာ သုံးရမှာမို့။

2. **Transcript ကို Gemini ပို့မယ် → First-person + 90% ပြန်ပါအောင် ပြင်ရေးမယ်**
   - Gemini က transcript ကို အဓိကဇာတ်ကောင် ကိုယ်တိုင် သူ့အကြောင်း ပြန်ပြောနေသလို (ပထမလူ / ကျွန်တော်-ကျွန်မ) ပြန်ရေးမယ်။
   - မူရင်း အကြောင်းအရာ၏ **90% ပြန်ပါရမယ်** (အကျဉ်းချုံးလိုက်တာ မဖြစ်ရ)။
   - တိုင်းတာပုံကို အောက်ပိုင်း "အတည်ပြုပြီးသား ဆုံးဖြတ်ချက်များ" တွင် အတိအကျ သတ်မှတ်ပြီးဖြစ်ပါသည်။ Link/video တိုင်းအတွက် အနည်းဆုံး 90% ဖြစ်ပြီး မပြည့်သေးသော group များကို Gemini top-up လုပ်ရမည်။

3. **အသံ (voiceover) ထုတ်မယ် — ရွေးထားတဲ့ အသံတမျိုးတည်း**
   - Gemini output ကို voiceover လုပ်ပေးနိုင်တဲ့နေရာကို ပို့ပြီး ကိုယ်ရွေးထားတဲ့ အသံနဲ့ပဲ ပြောရမယ်။
   - အသံဖတ်ပြီး တကယ့် narration ကြာချိန်ကိုလည်း 90% target နှင့် ထပ်စစ်ရမည်။ Target ထက် သိသာစွာ တိုသော narration ကို ဆက်ပြီး render/delivery မလုပ်ရ။

4. **မူရင်း video နဲ့ အသံဖိုင် ညှိမယ် — အသံကို မညှိဘဲ video ကိုပဲ ဖြတ်မယ်**
   - အသံဖိုင်ကို speed ပြောင်း/stretch **လုံးဝ မလုပ်ရ**။
   - အသံအရှည်နဲ့ ကိုက်အောင် မူရင်း video ထဲက **မလိုတဲ့အပိုင်းတွေကို ဖြတ်ထုတ်ရုံပဲ**។
   - ⚠️ ဒါအလုပ်ဖြစ်ဖို့ script ကို အခန်း(segment)လိုက် timestamps နဲ့ ထုတ်မှရမယ် — အခန်းတိုင်း "အသံအပိုင်းရယ် + သူနဲ့ဆိုင်တဲ့ video အပိုင်းရယ်" တွဲဖြတ်/ဆက်ရမယ်၊ ဒါမှ ပုံနဲ့ အသံ လွဲမသွားဘူး။

5. **Final video ပြန်ပို့မယ် — MB များရင် ခွဲပို့မယ်**
   - ဖိုင်ကြီးရင် အပိုင်းလေးတွေ ခွဲပို့မယ် (ဥပမာ Telegram ဆိုရင် တစ်ပိုင်းစီ 45MB အောက် — လက်ရှိ bot က လုပ်နည်းအတိုင်း)။

## အကြံပြု n8n node flow (ပုံကြမ်း)

```
[Trigger: Telegram/Webhook – link လက်ခံ] → [စပြီ လို့ ပြန်ပြော]
→ [yt-dlp download (Execute Command)] → [ffprobe: duration/size]
→ [ffmpeg: audio ထုတ်] → [Transcript (timestamps ပါ)]
→ [Code: 90% ပစ်မှတ်တွက်] → [Gemini: first-person ပြန်ရေး (segment JSON)]
→ [Code+IF: 90% ပြည့်/မပြည့် စစ် → မပြည့် Gemini top-up loop]
→ [TTS: ရွေးထားတဲ့အသံ – segment လိုက်အသံထုတ်]
→ [ffmpeg: မူရင်း video ကို segment လိုက်ဖြတ် (အသံကို မထိ) → ဆက် → အသံထည့် mux]
→ [IF: MB ကြီး? → ခွဲဖြတ်] → [Final video ပြန်ပို့] → [temp ဖိုင်တွေ ရှင်း]
  └─ အဆင့်တိုင်း error ကိုင်တွယ်မှု + အခြေအနေ(progress) ပြန်ပြောမှု
```

## လုပ်လို့ရလား? — ရပါတယ်၊ ဒါပေမယ့် ဒါတွေ ထပ်လိုပါမယ်

### မဖြစ်မနေ လိုမယ့် ပစ္စည်း/နေရာ
- [ ] **n8n run မယ့်နေရာ (အရေးအကြီးဆုံး)** — video download/ဖြတ်တာက ffmpeg + yt-dlp လိုပါတယ်။ n8n Cloud မှာ ပစ္စည်းထည့်လို့မရ/Execute Command မရလို့ **self-host (Docker/VPS) ဒါမှမဟုတ် လက်ရှိ bot server ကို အလုပ်သမား(worker)အဖြစ် n8n က လှမ်းခေါ်တဲ့ပုံစံ** ထဲက တစ်ခု လိုပါမယ်။ MB ကြီးတာတွေ ကိုင်ဖို့ disk နေရာပါ လိုမယ်။
- [ ] **API key/secrets** — Gemini API key၊ transcript service key၊ အသံ(TTS) service key၊ (Telegram ဆိုရင်) bot token — n8n Credentials ထဲ သိမ်းမယ်။
- [ ] **ယာယီ သိမ်းနေရာ** — job တစ်ခုချင်း folder ခွဲသိမ်း + ပြီးရင်ရှင်းတဲ့ အစီအစဉ် (ဖိုင်ကြီးတွေ မစုအောင်)။

### ဆုံးဖြတ်ရဦးမယ့် အချက်တွေ
- [ ] Link ကို ဘယ်ကနေ ပို့ပြီး final video ကို ဘယ်ကို ပြန်ပို့မလဲ (Telegram လက်ရှိ bot လား?)
- [ ] Transcript ကို ဘယ်သူ/ဘာနဲ့ လုပ်မလဲ — လူက ပေးထည့်မှာလား၊ Gemini ကိုယ်တိုင်လား၊ Whisper လား?
- [ ] "overley" ဆိုတာ ဘာကို ဆိုလိုတာလဲ — TTS service နာမည်တစ်ခုကိုယ်တိုင်လား၊ အသံထပ်တဲ့ အဆင့်ကို ခေါ်တာလား? **ရွေးထားတဲ့ အသံ** အတိအကျ ဘယ်ဟာလဲ?
- [ ] မူရင်း video ဘာသာစကား → script ဘာသာစကား (မြန်မာဘာသာပဲလား? ဘာသာပြန်ပါ ပါမှာလား?)
- [x] 90% ကို တိုင်းပုံ အတိအကျ — အောက်ပါ အတည်ပြုဆုံးဖြတ်ချက်များကို ကြည့်ပါ
- [ ] မူရင်း နောက်ခံ အသံ/တီးလုံး ထားမလား အကုန် အသံအစားထိုးမလား၊ စာတန်း(subtitle) ပါမလား
- [ ] Transcript ပဲသုံးရင် **စကားမပြောဘဲ မြင်ကွင်းပဲပြတဲ့ အစိတ်အပိုင်းတွေ ကျန်ခဲ့နိုင်တယ်** — Gemini ကို video ကိုပါ ကြည့်ခိုင်းရမလား၊ transcript ပဲ လုံလောက်လား
- [ ] အလုပ် တစ်ပြိုင်နက် ဘယ်နှခု လုပ်ခွင့်ပေးမလဲ (queue) + ကြာတဲ့အချိန် progress ပြန်ပြောမလား

## အတည်ပြုပြီးသား ဆုံးဖြတ်ချက်များနှင့် V1 အကောင်အထည်ဖော်မှု

အထက်ပါ checklist ထဲက အချက်တွေကို အောက်ပါအတိုင်း အတည်ပြုထားပါသည်။

- [x] **Link လက်ခံခြင်းနှင့် final video ပြန်ပို့ခြင်း** — လက်ရှိ Telegram bot ကိုပဲ သုံးပါမည်။ Bot က menu/settings/status/cancel တွေကို ဆက်ကိုင်တွယ်ပြီး n8n Webhook ကို job လွှဲပေးပါမည်။ Telegram webhook နှစ်ခု တပြိုင်နက် အပြိုင်မဖြစ်စေရန် n8n Telegram Trigger မသုံးပါ။
- [x] **Transcript** — Whisper (OpenAI-compatible API) ကို timestamp ပါဝင်သော segment များနှင့် သုံးပါမည်။ အသံကို အပိုင်းခွဲပို့နိုင်ရန်လည်း စီစဉ်ထားပါမည်။
- [x] **Voiceover** — လက်ရှိ Gemini TTS နှင့် Telegram Settings ထဲက ရွေးထားသည့် အသံကိုပဲ သုံးပါမည်။
- [x] **Heavy work လုပ်သည့်နေရာ** — yt-dlp/ffmpeg ပါပြီးသား လက်ရှိ Render bot server ကိုပဲ worker အဖြစ် သုံးပြီး n8n က stage အဆင့်ဆင့်ကို လမ်းညွှန်ခေါ်ဆိုပါမည်။
- [x] **Script ဘာသာစကား** — V1 တွင် transcript ကို Burmese ပထမလူ script အဖြစ်ပဲ ပြန်ရေးပါမည်။ မူရင်း video ဘာသာမတူလျှင်လည်း Burmese သို့ အဓိပ္ပာယ်တူအောင် ပြန်ရေးရပါမည်။
- [x] **90% တိုင်းတာပုံ (link/video တိုင်းအတွက်)** —
  1. Coverage setting ကို အနည်းဆုံး 90% ဟု သတ်မှတ်ရမည်။ 90% အောက် သိမ်းထားသော တန်ဖိုးဟောင်းများကို 90% သို့ မြှင့်ပြီး 95%/100% ရွေးထားမှုများကိုသာ ၎င်းအတိုင်း ထားရမည်။
  2. Whisper segment တွေကို worker က group ပြုလုပ်ထားပြီး Gemini က group တစ်ခုလျှင် scene တစ်ခုစီ ပြန်ပေးရမည်။
  3. Worker က group start/end နှင့် source segment ID တွေကို ကိုယ်တိုင်ထိန်းထားမည်။
  4. Script ထဲတွင် ကိုယ်စားပြုထားသည့် Whisper speech duration သည် ရွေးချယ်ထားသော coverage (အနည်းဆုံး 90%) အထက် ဖြစ်ရမည်။ Scene စာသားရှိနေရုံနှင့် covered မသတ်မှတ်ရ။
  5. Burmese စာသားပမာဏကို `source video duration (မသိလျှင်သာ speech-active duration) × coverage × characters/second` ဖြင့် target တွက်ပြီး source timeline အလိုက် group များသို့ ခွဲဝေကာ မပြည့်လျှင် top-up လုပ်ရမည်။
  6. တကယ့် TTS narration နှင့် final video ကြာချိန်ကိုပါ target နှင့် စစ်ပြီး ပမာဏမပြည့်လျှင် delivery မလုပ်ဘဲ failed ဖြစ်စေရမည်။
- [x] **Audio** — V1 တွင် မူရင်းအသံ/BGM ကို မထားဘဲ Gemini TTS narration တစ်ခုတည်း ထည့်ပါမည်။
- [x] **Subtitles** — V1 တွင် subtitle/caption burn-in မပါပါ။
- [x] **Video alignment** — narration ကို speed ပြောင်း/stretch/pad မလုပ်ပါ။ Scene အစကိုသာ align လုပ်ပြီး narration တိုလျှင် video အစိတ်အပိုင်းကိုဖြတ်ကာ, ရှည်လျှင် နောက် scene မစမီကြားထဲက footage ကိုသာ ချေးယူပါမည်။ မဖြစ်မနေလိုမှသာ နောက်ဆုံး frame ကို freeze လုပ်ပါမည်။

### V1 ကန့်သတ်ချက်
