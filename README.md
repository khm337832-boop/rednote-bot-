# Burmese subtitle bot

This branch replaces the active recap workflow with a Telegram subtitle workflow. Send a video or supported video link in a **private** chat. The bot downloads the source, uses Gemini to listen to short chronological audio windows and translate speech into timed Burmese captions, and sends a private editor link. In the browser, play the video, drag the caption, adjust its size, and correct any caption text or timestamps. Choose **Final video ပို့ရန်** to burn the captions into the original video and deliver all parts on Telegram. Original audio remains; if its codec cannot be copied into MP4 it is converted to AAC, not replaced with narration.

Version `subtitle-v1.5-timing-split-retry` validates timed subtitle responses before selecting a model answer. Known JSON envelopes and timestamp formats are supported; malformed, truncated or ambiguous empty responses are rejected. If a complete response contains invalid timings, the model is asked to re-listen to the same audio and return corrected times only for those cues. When no targeted repair is possible or it fails, an invalid-response audio window can be split and retried down to at most four 15-second windows. Both halves must succeed; local code does not invent times or silently omit failed windows. Provider/quota failures do not trigger splitting. Non-Burmese cues get a bounded text-only translation pass without changing timing or dropping cues. An empty chunk is accepted only when the model explicitly reports silence. Model-generated timing and translation still need review in the editor before export.

Version `subtitle-v1.8-transcribe-translate-cover` transcribes original speech into timed original-language cues first, then translates their text to Burmese in separate batches while preserving cue IDs and timing. Transcription and timing still depend on the provider, and the translation is not guaranteed correct or complete. Subtitle windows are checkpointed only after translation; if a provider failure occurs partway through a window, retry redoes that window. The editor can cover the bottom of the original video with an adjustable opaque black band (enabled by default); this also hides any picture under the band. Users can turn it off or change its height. Original audio is retained in the final video. Review the translation and cover placement before sending. Real-provider quality needs validation on actual videos.

Version `subtitle-v1.7-preview-progress` edits the Telegram preview message about every 15 seconds with estimated encoded-video percentage, elapsed time, and seconds since FFmpeg's output timestamp last advanced. The percentage stays below 100 until FFmpeg exits successfully, because finalizing the file can take time. An unchanged timestamp for 60 seconds is a warning, not proof that FFmpeg has hung. An unavailable Telegram connection can also prevent message updates. Preview retains its one-hour timeout.

Version `subtitle-v1.6-provider-retry-checkpoint` handles Gemini 503/429 capacity failures without silently shipping partial subtitles. Each fully validated 60-second window is checkpointed privately. If the provider is unavailable, the bot keeps the source and completed windows temporarily and offers `/retry` to resume at the first unfinished window; `/cancel` deletes the paused job. There is no background queue. Retry eligibility expires two hours after the latest provider failure; periodic cleanup may delete the files up to 15 minutes later. The data is lost on restart or deploy. A provider may remain unavailable, and the current failure that happened before this version cannot be resumed because its source was already removed.

The AI translation and timing are not guaranteed accurate: check the preview and edit mistakes before rendering. The browser preview approximates the final font layout and may differ slightly. Source video and editor sessions are held temporarily on the server; sessions expire after at most 24 hours and are lost on restart/deployment. Do not share the editor link. Gemini free-tier availability, quota, and supported models are controlled by Google; if unavailable the job fails rather than delivering an untranslated video. No paid service is required by this code, but a configured Gemini key must have access to a free tier.

## Limits

- Telegram's public Bot API limits bot downloads to 20 MB. For a larger Telegram upload, the bot sends a private, one-hour browser-upload link: choose the original video again, without splitting it. Alternatively send `/upload` in the private bot chat to request a link without first uploading the file to Telegram. The bot cannot fetch the original large Telegram attachment itself. Supported public video links also work. Browser uploads are streamed to temporary disk, and disk space, provider/proxy limits, network interruption or restart can still prevent an upload.
- Large results are split only after final rendering; the bot verifies part sizes and total duration, reports a failed partial delivery, and resumes at the first unsent part when retried with the same settings.
- Silent videos are reported rather than given invented subtitles. Audio crossing a 60-second boundary or difficult/noisy speech can need manual correction.
- Multiple sessions are private capability links. They are not durable storage; download the result and retain the source yourself.

## Deployment

The existing Render Docker service runs `subtitle_app.py`, retaining the existing `BOT_TOKEN`, `GEMINI_API_KEY`, `ADMIN_ID`/allowed-user and public URL configuration. `Dockerfile` installs ffmpeg and Noto Sans Myanmar. The Telegram webhook is authenticated with the existing derived or configured `TELEGRAM_WEBHOOK_SECRET`. No Whisper/OpenAI key, n8n, TTS, or payment setup is needed for the subtitle flow. The older `bot.py` remains as a library for proven downloads, Gemini calls, splitting and Telegram transport; its recap menus and worker routes are not exposed by the new entry point. The old n8n documentation describes the retired recap flow and is not part of the subtitle bot.

For local development install `requirements.txt`, ffmpeg/ffprobe with libass, and Noto Sans Myanmar, then run `python subtitle_app.py`. Telegram webhook/editor links require a public HTTPS URL (`RENDER_EXTERNAL_URL`). Set secrets through environment configuration, never in chat or source code. The service listens on `0.0.0.0:$PORT`; `/healthz` reports its version.

Tests: `python -m pytest -q`. Real Telegram/Gemini operation and the final translation must additionally be checked on a real job; offline tests do not establish translation accuracy or provider availability.
